# Build notes: frozen bounds, qualification and package gates

Development 0.1.0 uses the numeric contract in `contract.md` without automatic reductions. Bounds were resolved for the native toolchain before implementation: JSON 131072/depth64; AST64/depth16; NFA128; graph32/128; targets32; IDs32/labels16; product4096; relaxations100000; witness128/string8192; run4096; report65536; membership2000000; oracle2000000. Exceeding construction/input limits rejects input; exhausting certification/search limits gives unknown. These are limits, not benchmark or memory claims.

## Real metadata required by scripts

Source-side records live in `dependency-metadata/`, never under ignored cache directories. They contain collected data, not generated substitutes for registry metadata. `ocaml-regular-path-witness.opam.locked` must be generated by actual opam resolution for the authored `.opam`, from the project root. Neither CI nor an offline gate generates or repairs it.

The preparation-data adapter uses these explicit schemas:

- `dependency-metadata/inputs.sha256`: lines `64-lowercase-hex-digest`, two spaces, relative POSIX path. Covers the authored `.opam`, actual `.opam.locked`, artifacts manifest, platform metadata, system package metadata, every minimal-repository file and every collected notice. Duplicate paths, symlinks, missing files and digest drift fail.
- `dependency-metadata/artifacts.json`: object with `format: 1` and `artifacts` array. Each record has exactly `path`, `url`, `sha256`, `kind`. Kind `source` uses a path under `sources/`; exactly the qualified Dune/Yojson source archives and the three commit-pinned OCaml configuration extra-sources from the real opam metadata are required. Kind `deb` uses `debs/<official-filename>.deb`. Real official package URLs and SHA256 values come from preparation. No source outside that complete set is admitted. Artifact count is 2–512, each download at most 256 MiB.
- `dependency-metadata/system-packages.json`: collected official distribution package/version/license/provenance record. It is covered by the input digest manifest. The actual consumed artifacts are the `deb` records in `artifacts.json`; every copied artifact is checksum-verified before the offline local-deb installation. The pinned base plus that complete dependency closure must provide OCaml, opam, Python, native compiler/linker, bzip2, curl, CA certificates and ordinary POSIX tools. There is no floating apt installation in the Dockerfile.
- `dependency-metadata/opam-repository/repo` and `packages/`: actual minimal official repository records for the exact eleven-package closure, including their real source URLs/checksums. Do not synthesize metadata from the names below.
- `dependency-metadata/licenses/`: actual selected license texts and provenance, including compiler/runtime exception, Yojson, Dune and applicable bundled/distribution components.
- `dependency-metadata/platform.json`: collected measured record containing `system: "Linux"`, `machine: "x86_64"`, `libc: "glibc"`, and `sigaction` exactly `{size:152, handler_offset:0, handler_size:8, flags_offset:136, flags_size:4, sa_nocldwait:2}`. These ABI values were measured from the selected platform headers, not presented as portable assumptions. Runtime platform and pointer-size checks must also match.

The required installed opam closure is exactly: `base-bigarray.base`, `base-domains.base`, `base-effects.base`, `base-nnp.base`, `base-threads.base`, `base-unix.base`, `dune.3.24.2`, `ocaml.5.3.0`, `ocaml-config.3`, `ocaml-system.5.3.0`, `yojson.3.0.0`.

## Preparation and offline separation

`fetch-artifacts.py` only downloads hash-verified official artifacts from allowlisted official hosts, with checked redirects. It does not resolve dependencies. It writes a consumed checksum manifest under `build/artifacts/`; this output is not an authored lock. Docker builds from the public pinned Debian base and installs only verified debs, with normal root preparation capabilities, not a privileged container. Apt receives only the complete local, checksum-verified deb paths under Docker build `--network=none`, so it orders Pre-Depends correctly. No apt repository update is run; missing artifacts fail preparation. No public instruction depends on a private image.

Offline preparation restores an isolated `OPAMROOT=build/opam-root`, seeds its content-addressed cache from verified sources, initializes only the local minimal repository, creates `build/ocaml-switch`, and installs `--deps-only --locked --no-depexts`. Fetching is disabled with `OPAMFETCH=/bin/false`; no repository update is run. The outer namespace has no network. The actual switch prefix is obtained with `opam var --switch=... prefix`, not inferred. Exact closure and compiler/Dune versions are checked before other gates. The workspace must allow UID1000 to write `build/`; artifact preparation creates that directory writable for the isolated user. Source files need only be readable.

All compiler/tool launches use the acknowledged owned-child protocol. Every gate runs in a fresh isolated container, even when sharing the restored switch/cache. The fault gate is a separate terminal namespace. CI grants only read-only repository permissions and has job/step timeouts. No publishing or deployment is performed.

## Packaging

`/bin/sh scripts/package-offline.sh` creates deterministic-metadata uncompressed tar files with bounded counts/bytes. It rejects symlinks and special files. Extraction manually validates unique relative paths and regular-file types; it does not call unrestricted tar extraction. Source inventory includes code, scripts, workflow, docs, examples, lock and real metadata, excluding build outputs and repository control data. The package is built from a fresh extraction under `/tmp`, not from the checkout.

The installed tar includes the CLI, Dune-installed library files (`.cmi`, `.cmxa`, `.a` and other installed files), docs, example, independent consumer, source archive and collected dependency notices. The extracted CLI is run outside the checkout. A fresh `ocamlopt` consumer links only the installed library and the prepared Yojson dependency, replays graph and NFA evidence for every solved demo case and checks membership. A computed SHA256 package inventory is stored under `build/`.

The source and installed archives are capped at 4096 files, 32 MiB per member, 64 MiB aggregate payload and 65 MiB encoded tar. The offline `/tmp` budget is 256 MiB. These are packaging failure limits, separate from query semantics. A failure is terminal, not evidence of package success.

## Shared gates retained

Dependency preparation, offline resource isolation, owned subprocess identity, read-only/pinned CI, extracted-package/installed-consumer quality, and bounded independent evidence are all required implementation and release gates. Passing one is not a substitute for the others. Release review must retain real locks, provenance, complete notices, successful offline evidence, and review of tool process behavior. Publication is not part of any workflow here.
